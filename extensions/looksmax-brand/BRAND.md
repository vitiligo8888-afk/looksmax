# Looksmax.lat — brand

The identity: one mark, one lockup, one palette, and the rules for using them.
Every colour pair below has a measured contrast ratio, produced by
`tools/palette.py`, which also generates `less/brand.less` from the same
numbers so the documentation and the stylesheet cannot drift.

---

## 1. The mark

The **chrigger head** — the character's own face, engraved. Horns, hair fringe,
brow, eyes and a smirk, cut out of one solid brass silhouette.

Master: `assets/mark.svg` (32×32, `currentColor`, `fill-rule="evenodd"`),
generated by `design/chrigger.py` → `design/mark-paths.json` → `design/master.py`.
Source illustration: `assets/chrigger/devil.png` (repo root).

**Why the devil face, and why engraved.** The operator's direction was "change
it to one of the chrigga pictures, the most fitting one for it (but diff than
the chris pfp)". All thirteen were cut out and rasterised at 16/32/64/192/512
on the plate, on white and on both of Chrome's tab strips
(`design/chrigger/02-ladder-all-faces.png`). What the renders showed at 16px:

| face | what it rendered as at 16px |
|---|---|
| angel | a beige blob under a grey smear — the halo is a 1px ellipse and dissolves |
| angry | a beige blob; the scowl that is the whole point is two grey smudges |
| chrigga | a brown blob |
| chrishammed | pink mush — the red-and-white keffiyeh check averages to pink, and the whole mark goes pale on the dark plate |
| devil | a beige blob **with two red points on top** — the only silhouette break in the set |
| error | the red badge survives, the face does not; it is a composite, not a mark |
| happy, neutral, sad, surprised | indistinguishable beige blobs; the reactions lane measured the same thing (`looksmax-reactions/proof/legibility.json`: happy/surprised 7.02 apart at 20px, neutral/sad 7.64) |
| nerd | the glasses vanish and the pointing hand makes a lopsided blob |
| rich | the sunglasses survive as a dark bar — **and it is Chris's avatar**, see below |
| thinking | the hand becomes a second blob below the first |

So the honest finding is: **no chrigger face survives 16px as a picture.** A
992×1056 illustration shrunk by 62× is mush, exactly as the machinist's square
search predicted. What shipped is therefore not the picture — it is the
picture reduced by the rule that search produced:

> Detail must degrade by **disappearing**, not by mushing. Cut the detail out
> of a solid silhouette instead of assembling the mark from separate strokes.

`design/chrigger.py` does that in five steps:

1. **Cut the background.** It is near-white but not flat: the border ring
   measures 247–255 across the thirteen files and every one carries a soft drop
   shadow under the hair and jaw, so a single-threshold colour key either
   leaves a grey halo or eats the forehead highlight. A flood fill from the
   border is a *connectivity* test, not a colour test, so it follows the shadow
   down; the artwork's continuous ink outline stops it leaking inside. Several
   files also carry a 1–3px dark frame from the generator (devil's left column
   reads 198 against a 250 field) which is cropped off first, or it anchors the
   bounding box at x=0.
2. **Un-premultiply** the anti-aliased edge ring against white. Without it every
   edge pixel ships with white mixed into it — invisible on a white page,
   a glowing outline on `--brand-surface`. Before/after on both surfaces:
   `design/chrigger/01-cutout-dark-light.png`.
3. **Separate** horns (saturated red: R−G > 55), the hair mass (dark, thick —
   survives a 13px opening) and the facial features (dark, thin — does not).
4. **Engrave**: fill the whole silhouette with brass, then knock the hair
   boundary, the horn boundary and the features back out as lines.
5. **Trim the neck** and potrace onto the 32-unit grid. The neck cut is
   measured, not styled: with it attached the 16px favicon read as a guitar
   pick, because the taper below the jaw is the widest thing in the bottom
   third and it swallows the horns proportionally.

Six other reductions were rendered and rejected first
(`design/chrigger/03-simplification-devil.png`): a flat silhouette is
featureless above 48px; hair-only line art is beautiful at 192px and mush at
16; brass-on-brass horns lose the silhouette break; the inverse (brass face,
hair knocked out) is too thin and vanishes; dark hair over a brass face is the
best of the set **on white** and disappears entirely on the dark plate, which
is where the favicon lives.

**Not the same face as Chris.** `looksmax-reactions/src/Console/ChrisCommand.php:96`
defaults `--face` to `rich`, so the Chris admin account wears the sunglasses.
The mark is `devil`. Different expression, different silhouette, no collision
in a post header where both appear.

**Optical sizes.** Two drawings, one silhouette, traced from **one** crop so
they stay in register — swapping between them at a breakpoint must not move
the head:

| file | used at | difference |
|---|---|---|
| `mark.svg` | ≥ 48px, header, admin, masks | the engraving: horns, fringe, brow, eyes, smirk |
| `mark-simple.svg` | ≤ 32px raster | the bare silhouette — the lines are sub-pixel there and read as grey noise |

At 16px what is left is a brass horned head, which is the right thing to lose
detail down to. `design/chrigger/05-built-favicons.png` is the built PNGs on
Chrome's light and dark tab strips at 14× magnification.

**Clear space** is one horn-height on all sides. **Minimum size** is 16px for
the plated icon, 24px for the bare mark.

Never: recolour the mark outside the brass ramp, outline it, add a gradient to
it, rotate it, or reintroduce the horns in red — red is not in the palette and
`--brand-danger` is a status colour with a job.

### The superseded mark

The previous mark — a **graduated machinist's square**, chosen from eight
directions over five refinement rounds — is kept, not deleted:
`design/superseded/square-*.svg`, plus the favicon and OG card it produced.
The exploration that produced it is still in `design/explore*/` and the sheets
`design/out*-sheet-*.png`, and the two rules it established are the reason this
mark is drawn the way it is (see above). It was replaced on operator direction,
not because it failed: it measured well and read cleanly at 16px. The brief
changed from "an instrument means measured" to "the forum's character is the
mark".

Its abstract graduation motif survives where it is not acting as the mark: the
welcome banner's foot rule (`less/forum.less`) and `assets/art-empty.svg`.


## 2. The lockup

`assets/lockup.svg` — mark + `Looksmax.lat`, baselines aligned, the mark's foot
on the text baseline.

- Typeface: **Archivo ExtraBold (800)**, tracking −0.032em.
- Mark height: **1.85 × cap height**. The machinist's square filled its 32-unit
  box edge to edge and 1.42× was right for it; the head does not — it is a head
  inside a square canvas with air at the corners, so at the same nominal height
  it reads about a fifth smaller. 1.85× restores the weight.
- Gap: 0.34 × cap height.
- In the forum header the lockup is boxed at **42px** (32px under 768px wide),
  up from 30/24: `less/forum.less`. Rendered:
  `design/proof/chrigger/header-1440.png`.
- The full stop is brass; the rest of the word is ink. On white the stop is
  `brass-700`, because `brass-500` on white measures 1.71:1.

The wordmark ships as **outlines, not `<text>`**. An SVG logo containing `<text>`
renders in whatever font the viewer has: in an e-mail client, in a Slack unfurl
or on a machine where the webfont request failed, it silently becomes Arial.
`design/master.py` shapes the string through HarfBuzz (so the advances and
kerning are the ones Archivo specifies) and pulls the outlines with fontTools.

Variants: `lockup.svg` (dark surfaces), `lockup-light.svg` (white: e-mail,
print), `lockup-mono-light.svg` / `lockup-mono-dark.svg` (one colour),
`lockup-stacked.svg` (centred, for square spaces).

Twelve candidate typefaces were set at the size the header actually uses, not
at specimen size (`design/wordmark.ts`, output `design/out-word-WORDMARK.png`).
Archivo 800 won on being the most solid at 23px without becoming a slab; Chivo
800 was the closest runner-up; Manrope, Plus Jakarta and Geist read too
friendly for a board whose tone is blunt.

## 3. Colour

Ramps are interpolated in **OKLab**, not sRGB. Scaling a hex toward white in
sRGB desaturates and hue-shifts — the classic symptom is a light gold that
comes out pink. Steps have both an absolute lightness target (so `brass-200`
and `azure-200` weigh the same on the page) and a minimum separation from the
anchor (without it, `azure-500` and `azure-600` resolved to the same hex,
because azure's own lightness sits on the 600 target).

### Surfaces — sampled from the running forum, not invented

| token | hex | where |
|---|---|---|
| `--brand-void` | `#070910` | scrims, deepest wells |
| `--brand-header` | `#0b0e14` | the app header; also `theme-color` |
| `--brand-bg` | `#0e1116` | page background |
| `--brand-surface` | `#12161c` | cards, posts, list rows; the icon plate |
| `--brand-raised` | `#1a2029` | inputs, chips, nested blocks |
| `--brand-hover` | `#232c39` | hover and pressed |
| `--brand-line` | `#232c39` | decorative hairline |
| `--brand-line-strong` | `#5f6d82` | control boundaries |

The first three were read off `look-audit/index-1440.png` with a pixel sampler
rather than copied from a stylesheet, because the stylesheet and the render had
already diverged.

### Brass — primary

`100 #fff7ea` · `200 #ffe7c1` · `300 #ffd99a` · `400 #f3cc8a` · **`500 #e8c07d`**
· `600 #c29e62` · `700 #a18049` · `800 #745929` · `900 #473105`

500 is canon, not a choice: it is already the value in the `settings` table
(`theme_primary_color`), in the Gold rank and in the VIP tier. Three things
outside this lane depend on it.

### Azure — secondary

`100 #eef4ff` · `200 #dbe7fe` · `300 #c7dafe` · `400 #b3ccff` · **`500 #7aa2f7`**
· `600 #688ddb` · `700 #5475bc` · `800 #34508b` · `900 #162a5a`

Links, focus rings and the Looksmax+ tier. The focus ring is azure and not
brass deliberately: brass sits close in hue to the surfaces and a brass ring on
a brass button is invisible.

### Ink

`--brand-ink #eef2f7` · `--brand-ink-dim #aab5c6` · `--brand-ink-faint #8b96a8`
· `--brand-ink-invert #0e1116` (on brass, on white).

### Semantic

`--brand-ok #7fd18b` · `--brand-warn #f0b352` · `--brand-danger #ff8fa3`
· `--brand-info #7aa2f7`.

### Rank and tier colours

Mirrored into `--brand-rank-*` and `--brand-tier-*` from
`extensions/looksmax-ranks/src/Catalog.php`, which owns them. `palette.py`
parses that file rather than restating the values, so the two cannot drift, and
it measures them: anything failing is reported as a handoff item, never
silently corrected here.

## 4. Measured contrast

WCAG 2.1, computed from relative luminance. Text needs 4.5:1; UI components and
control boundaries need 3:1 (1.4.11). Reproduce with `python3 tools/palette.py`.
Full table, all 78 pairs: `design/contrast.json`.

### Text on the four dark surfaces

| foreground | bg `#0e1116` | surface `#12161c` | raised `#1a2029` | header `#0b0e14` |
|---|---|---|---|---|
| ink `#eef2f7` | 16.82 | 16.14 | 14.56 | 17.18 |
| ink-dim `#aab5c6` | 9.13 | 8.76 | 7.90 | 9.32 |
| ink-faint `#8b96a8` | 6.33 | 6.07 | 5.48 | 6.46 |
| brass-500 `#e8c07d` | 11.05 | 10.60 | 9.56 | 11.28 |
| brass-400 `#f3cc8a` | 12.44 | 11.94 | 10.77 | 12.70 |
| brass-600 `#c29e62` | 7.53 | 7.22 | 6.52 | 7.69 |
| azure-500 `#7aa2f7` | 7.51 | 7.21 | 6.50 | 7.67 |
| ok `#7fd18b` | 10.26 | 9.85 | 8.88 | 10.48 |
| warn `#f0b352` | 10.15 | 9.74 | 8.79 | 10.37 |
| danger `#ff8fa3` | 8.74 | 8.39 | 7.57 | 8.93 |

### On brass and on white

| pair | ratio | required |
|---|---|---|
| ink-invert `#0e1116` on brass-500 | 11.05 | 4.5 |
| ink-invert on white | 18.91 | 4.5 |
| brass-800 `#745929` on white | 6.56 | 4.5 |
| brass-700 `#a18049` on white | 3.68 | 3.0 (large / the lockup's stop) |
| brass-500 on white | **1.71** | — never permitted to carry meaning |

### The icon, against browser chrome

| pair | ratio |
|---|---|
| brass mark on the `#12161c` plate | 10.60 |
| plate on Chrome's light tab strip `#dee1e6` | 13.84 |
| brass mark on Chrome's dark tab strip `#202124` | 9.40 |

This is why the favicon is plated. Bare brass on a light tab strip measures
1.71:1 and is invisible; on a dark strip the plate recedes into the chrome and
what is left is exactly the bare mark, which is the correct fallback rather
than an accident.

### Control boundaries

`--brand-line-strong` is `#5f6d82` — 3.60 on bg, 3.45 on surface, 3.12 on
raised. The first value tried was `#3d4a5e`, which measured **2.11** and would
have shipped a control outline that fails 1.4.11. It looked fine to someone who
already knew where the input was.

### Rank and tier colours on `--brand-surface`

greycel 4.93 · iron 7.20 · bronze 6.34 · silver 11.19 · gold 10.60 ·
platinum 10.93 · diamond 11.66 · master 6.67 · luminary 9.50 · ascended 18.15
· tier-standard 4.93 · plus 7.21 · vip 10.60 · elite 7.84 · founder 6.86.

All pass 4.5:1. Greycel and Standard, both `#7c8695`, are the tightest at 4.93
and have no headroom for a darker surface than `#12161c`.

## 5. Type

| role | face | notes |
|---|---|---|
| display | **Archivo** 700/800 | `--brand-font-display`. Self-hosted, latin subset, ~11KB per weight, OFL (`assets/font/OFL.txt`). Wordmark, hero titles, admin headings. |
| UI and body | system stack | unchanged. A forum is read, not looked at; a webfont on body text costs a render-blocking hop for no legibility gain. |
| mono | system mono stack | unchanged. |

Self-hosted rather than pulled from Google: a third-party font request on a
forum where members post photographs of their own faces is a privacy leak, and
`font-display: swap` keeps the header readable if it fails.

Tracking: `--brand-tracking-display` −0.02em for headings,
`--brand-tracking-lockup` −0.032em for the wordmark.

## 6. The icon set

Generated by `tools/build-assets.ts` from the SVG masters, through Chromium —
the renderer a browser will actually use. ImageMagick's SVG path ignores
`fill-rule="evenodd"` in some builds and fills the graduations back in.

| file | size | purpose |
|---|---|---|
| `favicon.ico` | 16, 32, 48, 64 | multi-resolution; what crawlers and Windows shortcuts fetch |
| `favicon-16.png`, `favicon-32.png` | 16, 32 | from `icon-small.svg` |
| `icon.svg` | any | plated SVG favicon |
| `apple-touch-icon.png` (+167, +152) | 180/167/152 | full bleed, no alpha, no corner radius of our own — iOS applies both |
| `icon-192.png`, `icon-512.png` | 192, 512 | manifest `purpose: any` |
| `icon-maskable-192/512.png` | 192, 512 | manifest `purpose: maskable`; mark at 56% so a circle crop keeps it whole |
| `og.png` | 1200×630 | Open Graph and `summary_large_image` |
| `email-header.png` | 1200×208 (2×) | transactional mail band |
| `site.webmanifest` | — | written by the same script, so the icon list cannot drift from the files produced |

`.webmanifest` is served as `application/manifest+json` by a location block in
`nginx.conf`; `mime.types` has no entry for it and Safari rejects
`application/octet-stream`, which makes Add to Home Screen fall back to a
screenshot of the page.

Proof at the sizes a user sees, from the live URLs:
`design/proof/icon-proof.png`.

## 7. Where it is wired

| surface | mechanism |
|---|---|
| header lockup | `logo_path` setting → core renders `<img class="Header-logo">` |
| browser icon | `favicon_path` setting, plus the full set from `src/Head.php` via `Document::$head` |
| share cards | `src/Head.php` — og:*, twitter:*, absolute URLs |
| `theme-color` | `src/Head.php` overrides core's, which uses the brass accent and paints Android's address bar gold |
| welcome banner | `less/forum.less`, `.Hero.WelcomeHero` |
| mobile header | `less/forum.less` — core hides the whole header inside the drawer on phones; the bare mark is put back into the visible bar |
| 404, 500, password reset, e-mail confirm | `views/` via `Extend\View->extendNamespace`, which prepends ahead of core |
| admin panel | `less/admin.less` |
| print | `@media print` in `less/forum.less` |
| forum copy, admin address, mail from | `tools/apply-identity.php` (idempotent; `--check` reports drift) |

## 8. Reproducing

```
python3 design/chrigger.py [face]        # cut, engrave and trace the head -> design/mark-paths.json
python3 design/master.py                 # SVG masters from geometry + font outlines
python3 tools/palette.py --write         # brand.less + contrast.json + the numbers above
bun tools/build-assets.ts                # every PNG, favicon.ico, site.webmanifest
docker exec flarum-app php /flarum/extensions/looksmax-brand/tools/apply-identity.php
docker exec flarum-app php /flarum/app/flarum assets:publish
bash tools/verify.sh https://<forum>     # 43 assertions against the live site
```

`chrigger.py` needs `numpy`, `pillow`, `scipy` and `potrace`; `master.py` needs
`fonttools`, `uharfbuzz` and `brotli`; `build-assets.ts` needs bun, Chromium and
ImageMagick, and runs on the build host, not the laptop. `mark-paths.json` is
committed, so rebuilding the SVGs does not require the first step.

`design/shot-header.ts` screenshots the header with the brand assets forced
back onto the local origin — see HANDOFF-BRAND.md §12 for why a plain
screenshot of this box shows a stale logo.
